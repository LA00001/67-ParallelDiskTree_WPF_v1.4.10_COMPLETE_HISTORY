# Parallel Disk Tree — v1.3.0 Auto Benchmark + 7 складных панелей (WPF)

**Windows graphical UI** — C# / WPF / .NET 8 / Visual Studio 2022.

## Запуск

1. Распаковать ZIP в **новую** папку.
2. Открыть `ParallelDiskTree.sln` в Visual Studio 2022 (workload **.NET desktop development**, установлен .NET 8 SDK).
3. `Build → Rebuild Solution` (Debug или Release, лучше Release для честных замеров), затем `F5` или `Ctrl+F5`.
4. Ввести корень (например, `C:\` или другую папку). Интерфейс Windows/WPF, не CMD.

**Пакет содержит исходный билд, а не скомпилированный Windows `.exe`**: на стороне создателя архива невозможно выполнить WPF-компиляцию в Windows. Не считать статическую проверку подтверждением компиляции.

## Режимы

- **Сканировать**: выбранный в поле «РЕЖИМ» алгоритм (последовательный 1 или параллельный N, где N редактируется в диапазоне 1..64).
- **A/B тест**: последовательный 1 против параллельного N, порядок можно поменять флажком.
- **Автобенчмарк**: список `1,2,4,8,16,32` (редактируемый) и `3` повтора (редактируемое 1..5). **Важно: значение 1 в списке автоматического теста означает последовательный алгоритм; 2,4,... означают параллельный с соответствующим числом исполнителей.** Чтобы измерить *параллельный с одним исполнителем*, используйте кнопку «Сканировать» с N=1.
- По умолчанию **6 режимов × 3 повтора = 18 полных проходов**. Для диска в 1,8 млн объектов это может занять ДЕСЯТКИ минут. «Стоп» прерывает текущий проход и не начинает следующий.
- Первый повтор — по возрастанию N, второй — по убыванию, третий — циклически сдвинутый порядок. Это уменьшает, но не устраняет влияние файлового кэша Windows.

## Результаты на экране

- Точная локальная дата/время начала и окончания, длительность замера `Stopwatch`, количество файлов/папок, логические байты, объекты в секунду и ошибки.
- **Сводка** по каждому режиму: количество полных проходов **без ошибок**, медиана, лучший и худший результат, ускорение относительно медианы последовательного 1, средняя загрузка процесса CPU, среднее время ожидания в очереди, время обработки каталогов и простой исполнителей.
- **Данные: `=` или `Δ`** — полные проходы без ошибок вернули одинаковые или разные суммарные количества файлов, папок и байтов. Детальные счётчики каждого запуска видны в нижней таблице. Изменение файлов во время тестирования часто создаёт такие расхождения.
- **Поток·секунды** — накопленные времена всех исполнителей; их сумма может быть больше реального времени сканирования. «Каталоги» включает перечисление и обработку записей, НЕ является чистым временем дисковых операций.
- **Ожидание очереди (мс)** — среднее время от постановки папки в очередь до начала её обработки. В последовательном режиме очередь `Channel` не используется; выводится `—`.
- **Простой (поток·с)** — суммарное время, когда параллельные исполнители ожидали новую папку из очереди; может быть больше реальной длительности.
- **CPU%** — `Process.TotalProcessorTime / (elapsed × Environment.ProcessorCount) × 100`. Это приблизительная средняя нагрузка ВСЕГО ПРОЦЕССА (включает WPF UI), нормированная на все логические процессоры. Это не CPU отдельного worker и не нагрузка диска. Значения не обязаны достигать 100% при интенсивном сканировании.

## Логи

Открываются кнопкой **«Логи ↗»**, путь:

`logs/` рядом с EXE (изменено в версии 1.4.9; предыдущие версии использовали профиль Windows)

- `benchmarks_v1_2.csv`: подробные строки всех запусков v1.2, включая режим, N, номер повтора, порядковый номер, временные метки, количество объектов/байтов, CPU, показатели очереди.
- `median_summary_v1_2.csv`: агрегированные медианы, ускорение, диапазоны файлов/папок/байтов, показатели CPU/очереди/каталогов.
- `events.log`: короткая запись на проход + общий вывод; ротация ~1 MiB в `.1`.
- **Никаких записей логов во время сканирования.** Вся серия накапливает метрики в RAM и сохраняет CSV/LOG лишь после завершения (либо после нажатия «Стоп» и завершения активного прохода). Файлы предыдущих версий `benchmarks.csv` не меняются (разная схема колонок).
- Если приложение аварийно закроется *до* конца серии, ещё не записанные логи этой серии пропадут. Во время продолжительного теста данные видны в UI.

## Важные ограничения

- Сканер **только читает метаданные**. Не удаляет, не перемещает и не редактирует файлы. Дерево последнего прохода можно сохранить отдельной кнопкой «Экспорт дерева CSV».
- Не открывает содержимое файлов: суммируются логические длины, а не реально выделенные на диске блоки. Жёсткие ссылки могут дублировать логический размер. Каталоги с junction/symlink не обходятся для предотвращения циклов.
- `EnumerationOptions.IgnoreInaccessible=true`: часть защищённого содержимого может быть пропущена **без** зарегистрированной ошибки. `errors=0` не гарантирует полного доступа ко всему системному диску.
- Нет атомарного снимка NTFS: содержимое диска может меняться между проходами. Сравнивать медианы предпочтительно на неизменной папке/разделе.
- Результаты дерева хранятся в RAM. Перед новым проходом прошлое дерево исключается из GUI и запускается сборка мусора **вне замера**. На очень больших папках может потребоваться много памяти.
- Один замер или даже три — ещё не доказательство абсолютной скорости: влияют фоновая работа Windows/антивируса, скорость SSD/HDD, кэш ОС, температура, заполнение диска.
- Экспериментальный вывод «самый быстрый» следует трактовать осторожно, если повторов не хватает или счётчики файлов/папок/байтов отличаются.

## Состав

- `ParallelDiskTree.sln` / `.csproj`: проект Windows WPF `net8.0-windows`.
- `App.xaml`, `App.xaml.cs`: тема интерфейса и WPF приложение.
- `MainWindow.xaml`, `.cs`: UI сканирования, дерева, A/B и автобенчмарка.
- `ScanEngine.cs`: последовательный stack DFS и динамический `Channel` с N исполнителями, счётчики и инструментирование на уровне каталогов.
- `Benchmarking.cs`: план чередования, медиана/диапазон, сравнение счётчиков, CSV и краткие логи.

## Для воспроизведения

Для сравнения с тестами v1.1 сначала попробуйте `1,4,8,16` и `2` повтора (8 проходов), затем `1,2,4,8,16,32` × `3` в Release, при стабильной фоновой нагрузке. Проверьте `Δ`: если счётчики изменились, не делать сильных выводов только по времени.

## v1.3.0 — 7 кнопок сворачивания (по зелёным меткам на скриншоте)

Добавлены **ровно семь** кнопок `▼/▶` (свернуть/развернуть) в заголовке окна:

1. Заголовок и подзаголовок приложения (основные кнопки запуска / остановки остаются на месте).
2. Режимы и настройки (тип сканирования, N, A/B, параметры автобенчмарка).
3. Текущая статистика (счётчики, таймер и полоска прогресса).
4. Основное содержимое бенчмарка (описание сравнения и обе таблицы).
5. Таблица медиан.
6. Таблица всех проходов.
7. Дерево папок слева (ширина колонки уменьшается с текущего значения до 64 px, справа освобождается пространство для списка файлов; повторное раскрытие восстанавливает ширину).

Состояния независимы: например, сворачивание блока бенчмарка не сбрасывает состояние его двух вложенных таблиц. По умолчанию таблицы медиан и всех проходов свёрнуты, чтобы после запуска оставалось место для дерева папок; их заголовки и треугольники видны и доступны. Никакие результаты не стираются и не прекращается сканирование при сворачивании. Все вызовы работают на UI-потоке. Движок `ScanEngine.cs`, бенчмаркинг и дисковое логирование не изменены относительно v1.2.0.

> Важно: ZIP содержит исходники `.sln` для сборки в Visual Studio на Windows. В текущей среде невозможно выполнить WPF-компиляцию с WindowsDesktop SDK, поэтому полная Windows-сборка требует проверки пользователем.
