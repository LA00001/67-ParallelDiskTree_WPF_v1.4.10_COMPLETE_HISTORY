# Parallel Disk Tree v1.4.1 — 🔥 Адаптивный

Windows / WPF / .NET 8, исходники `.sln`, без сторонних пакетов.

## Запуск

1. Откройте `ParallelDiskTree.sln` в Visual Studio 2022 с установленными .NET 8 SDK и **.NET desktop development**.
2. **Сборка → Пересобрать решение**, затем F5.
3. Выберите каталог (например, `C:\`).
4. Нажмите **🔥 Адаптивный** (кнопка сверху) или выберите **🔥 Адаптивный (4→32)** в списке «Режим» и нажмите «Сканировать».
5. Дождитесь завершения. «Стоп» отменяет обход, предварительно собранные данные сохраняются, но результат будет неполным.

## Режимы и совместимость

- **Последовательный (1)** — прежний режим.
- **Параллельный (N)** — прежний режим с редактируемым N = 1..64 (4 по умолчанию).
- **🔥 Адаптивный** — НОВЫЙ режим, *один* проход. Старт с 4 разрешённых исполнителей, динамические ступени 8 / 16 / 32, уменьшение до 16 / 8 / 4 при явной деградации. Количество *созданных* async worker задач — максимум 32, лишние ожидают и не извлекают новые каталоги. Уже выполняющаяся операция завершается перед парковкой потока, поэтому мгновенное число активных задач может чуть превышать цель N. Дерево сканируется один раз: **разрешённые исполнители меняются в рамках общей очереди**.
- **A/B тест**, **Автобенчмарк** 1/2/4/8/16/32 × 3 — сохранены, тестируют фиксированные режимы.
- **7 кнопок ▶ / ▼** — сохранены в прежних местах.

## Эвристика адаптации

Контроллер работает независимо от UI. Раз в ~2 секунды делает один пробный замер; раз в ~8 секунд оценивает число найденных объектов, заполненность очереди и активность исполнителей.

- Если очередь содержит запас работы, почти все текущие исполнители активны и признаков перегрузки нет — пробует следующую ступень N.
- Если после роста N скорость падает более чем на 30% относительно предыдущего окна или показатель Windows сообщает одновременно высокий % Disk Time и задержку чтения/записи > 35 мс — уменьшает N вдвое. После снижения даёт ~24 секунды до следующего увеличения.
- Не увеличивает N, когда остаётся мало параллельно доступных подпапок.
- **Важно:** скорость зависит от сложности каталогов и кэша Windows. Это практическая **эвристика**, а не гарантированный оптимизатор или доказательство эффекта увеличения N.

## Активность накопителя: реальные счётчики Windows PDH

На Windows с доступными счётчиками **LogicalDisk(буква тома)** берутся:

- `% Disk Time` — системный показатель занятости тома. Он **может превышать 100%** и **не равен физической загрузке накопителя в процентах**.
- `Avg. Disk sec/Transfer` — средняя задержка I/O; в UI миллисекунды/операцию.
- `Disk Bytes/sec` — общий обмен данными, в UI MiB/с.

Это I/O **всех процессов на томе**, не только Parallel Disk Tree. Данные из метаданных могут обслуживаться из RAM-кэша. Если счётчики недоступны, показывается **н/д**; сканирование продолжается, адаптация использует скорость и очередь.

## Логи

Сканирующий код не пишет лог на каждый файл. Результаты сохраняются **после остановки секундомера** в `logs/` рядом с исполняемым приложением (при запуске из Visual Studio — внутри `bin/Debug/net8.0-windows/`):

- `benchmarks_v1_2.csv` — совместимый журнал результатов всех режимов; в режиме Adaptive N=32 означает **максимум**, не число, использованное весь проход.
- `median_summary_v1_2.csv` — стандартные сводные результаты (одиночный adaptive результат не является честной медианой A/B).
- **`adaptive_samples_v1_4.csv`** — каждые ~2 секунды: локальная дата, прошедшее время, цель N, активные, очередь, объекты/с, PDH Disk Time, latency, байт/сек, принятое решение.
- `events.log` — краткая запись о каждом проходе.

Известные ограничения: размера папки «мгновенно» у Windows нет; размеры суммируются на основе перечисления файлов. Данные для деревьев содержатся в памяти, поэтому большие диски расходуют RAM. Права на каталог и работающие приложения могут мешать целостности результата; это не транзакционный снимок диска. Ничего не удаляется и не перемещается.

## Самопроверка на Windows

1. Соберите решение; должно быть 0 ошибок компиляции.
2. Просканируйте тестовую папку (например, 5000+ файлов, вложенность 5+) сначала «Параллельный (4)», затем «🔥 Адаптивный»; сравните файлы, папки и байты.
3. Запустите адаптивный проход на диске с большим числом подпапок; убедитесь, что цель N меняется в таблице, а `adaptive_samples_v1_4.csv` содержит соответствующие строки.
4. Нажмите «Стоп» во время обхода; убедитесь, что окно остаётся отзывчивым, а сканер корректно завершается.
5. Если PDH показывает н/д, проверьте Windows Performance Counters, но не считайте это ошибкой сканирования.

В текущей среде полноценная компиляция Windows/WPF не выполнялась. Необходимо проверить сборку в Visual Studio на Windows.
